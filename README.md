# Loophole Forge

Build and release automation for Loophole. This repo contains **no product code**;
it builds and ships the CLI and the desktop app from
[`loophole-ai/loophole-app`](https://github.com/loophole-ai/loophole-app).

## Repos

| Repo | Purpose |
|---|---|
| [`loophole-ai/loophole-app`](https://github.com/loophole-ai/loophole-app) | Source code |
| [`loophole-ai/forge`](https://github.com/loophole-ai/forge) | This repo — build + release automation |
| [`loophole-ai/cli`](https://github.com/loophole-ai/cli) | CLI release assets only |
| [`loophole-ai/desktop`](https://github.com/loophole-ai/desktop) | Desktop release assets only |

Separate release repos keep each product's `releases/latest` independent, which
is what the desktop updater depends on.

## Workflows

| Workflow | What it does |
|---|---|
| `cli-builder` | Builds 12 CLI targets, publishes npm packages, creates release `v<version>` in `loophole-ai/cli` |
| `desktop-builder` | Packages macOS/Windows/Linux installers, creates release `v<version>` in `loophole-ai/desktop` |
| `homebrew` | Updates `loophole-ai/homebrew-tap` without rebuilding |

## CLI (`cli-builder`)

Inputs: `version` (e.g. `1.0.8`), `ref` (default `loophole`), `publish_npm`,
`publish_release`, `publish_homebrew`.

1. Builds all 12 targets on Linux (Bun cross-compiles macOS/Windows)
2. Publishes the 12 platform packages, then the `@loophole-ai/cli` launcher (`latest` tag)
3. Packages `loophole-<target>.zip` / `.tar.gz` + `SHA256SUMS` + `install.sh`
4. Creates/updates release `v<version>` in **`loophole-ai/cli`**
5. Optionally updates the Homebrew tap

Tag pushes (`v1.0.8`) run the same pipeline with npm + release enabled.

## Desktop (`desktop-builder`)

Inputs: `version` (e.g. `1.0.0`), `cli_version` (published CLI to bundle),
`ref`, `publish_release`.

Matrix (native runners — installers cannot be cross-built):

| Target | Runner |
|---|---|
| `aarch64-apple-darwin` | `macos-14` |
| `x86_64-apple-darwin` | `macos-14` (`--x64`) |
| `x86_64-pc-windows-msvc` | `windows-latest` |
| `x86_64-unknown-linux-gnu` | `ubuntu-latest` |
| `aarch64-unknown-linux-gnu` | `ubuntu-24.04-arm` |

Each job downloads the published CLI platform package from npm, lays it out as
`packages/cli/dist/cli-<target>`, runs `prepare.ts` → `electron-vite build` →
`electron-builder`, then uploads installers and `latest*.yml` manifests. A final
job creates release `v<version>` in **`loophole-ai/desktop`** with everything
attached.

The app's updater provider is:

```
https://github.com/loophole-ai/desktop/releases/latest/download
```

so the `latest.yml`, `latest-mac.yml`, `latest-linux.yml`, and
`latest-linux-arm64.yml` assets must be on the latest desktop release. They are
generated by `electron-builder` and uploaded by the workflow.

### Signing

Desktop builds are **unsigned** by default:

- macOS: signing/notarization are skipped when no Apple credentials exist
  (`CSC_IDENTITY_AUTO_DISCOVERY=false`). Users must right-click → **Open**.
- Windows: `script/sign-windows.ps1` skips itself when Azure Trusted Signing
  secrets are absent. Users see a SmartScreen prompt.
- Linux: unsigned by design.

To sign later, add the Apple certificate/API key and Azure Trusted Signing
secrets and drop `CSC_IDENTITY_AUTO_DISCOVERY`.

## Homebrew (`homebrew`)

Manual workflow, input `version`. Regenerates `Formula/loophole.rb` and pushes it
to `loophole-ai/homebrew-tap` (must exist and be **public**).

Uses archives from release `v<version>` in `loophole-ai/cli` when `assets/`
exists, otherwise falls back to the immutable npm tarballs — so it works even
without a GitHub release.

```bash
brew install loophole-ai/tap/loophole
```

## Required secrets

| Secret | Scope | Used by |
|---|---|---|
| `NPM_TOKEN` | npm granular token, `@loophole-ai`, read/write, **2FA bypass on** | cli-builder |
| `RELEASE_TOKEN` | GitHub fine-grained PAT with `contents: write` on `loophole-ai/cli`, `loophole-ai/desktop`, and `loophole-ai/homebrew-tap` | all workflows |
| `HOMEBREW_TAP_TOKEN` | optional, overrides `RELEASE_TOKEN` for the tap | homebrew |

`GITHUB_TOKEN` alone is not enough: this repo cannot write to the release repos.

## Local usage

```bash
# CLI publish (after building packages/cli/dist in loophole-app)
APP_DIR=/path/to/loophole-app LOOPHOLE_VERSION=1.0.8 bun scripts/publish-cli.ts --dry-run

# Homebrew formula preview
LOOPHOLE_VERSION=1.0.8 ASSETS_DIR=/path/to/assets bun scripts/homebrew.ts --dry-run

# Desktop release preview (lists the assets it would upload)
LOOPHOLE_VERSION=1.0.0 DESKTOP_DIST=/path/to/assets GH_TOKEN=dummy \
  bun scripts/desktop-release.ts --dry-run
```

## Install channels

| Channel | Command |
|---|---|
| npm | `npm i -g @loophole-ai/cli` |
| Bun | `bun add -g @loophole-ai/cli` |
| curl | `curl -fsSL https://raw.githubusercontent.com/loophole-ai/forge/main/install.sh \| bash` |
| Homebrew | `brew install loophole-ai/tap/loophole` |

## Notes

- Publishing is idempotent: already-published versions are skipped, so re-running
  after a partial failure is safe.
- The launcher is published **last** and is refused unless all 12 platform
  packages are present (`CLI_ALLOW_PARTIAL=1` overrides for deliberate partial
  releases).
- AUR (`yay`/`paru`) is not automated: it needs an AUR account and SSH key.
- WinGet is not automated: it requires a `microsoft/winget-pkgs` submission.
- Renaming this repo is safe; only the raw `install.sh` URL above changes.
